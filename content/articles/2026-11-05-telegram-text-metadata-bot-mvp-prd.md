# Telegram 影片文本元数据 Bot：MVP 产品需求文档

版本：v0.5（博客发布版）。日期：2026-11-05。

配套文档：[MVP 技术方案](./2026-11-05-telegram-text-metadata-bot-mvp-technical-design.md)。

> 发布说明：本产品已部署，入口为 [JAVIndexBot](https://t.me/JAVIndexBot)。下文定义产品要求；上线不代表全部验收项已完成。真实 API 搜索、详情、账户接口和用户启动/年龄确认已验证；完整中文、日文实机流程及真实筛选效果仍需继续验收。具体核验范围见第 12 节。

本文定义一个只提供影片文本元数据查询的 Telegram Bot。产品不提供视频播放、预览流、磁力、torrent、下载地址或其他媒体访问能力。首版重点验证第三方数据 API 在 Telegram 查询场景中的可用性和交互体验，不把自建数据采集、复杂推荐或增长方案带入 MVP。

## 1. 产品目标与边界

### 1.1 目标

用户在 Telegram 私聊中输入影片编号或关键词，能够：

1. 获得可读的文本搜索结果；
2. 用少量常用条件缩小结果范围；
3. 打开单条记录查看完整文本详情；
4. 在结果列表和详情之间返回，不丢失查询条件和页码；
5. 在中文和日文界面之间切换，并在后续会话中保留选择。

首版验证的是“查询入口 + 上游数据转译 + Telegram UI”这一闭环，不验证获客、付费、广告或自建数据资产。

### 1.2 内容边界

产品只展示经过字段映射的文本元数据，例如影片编号、标题、发行日期、时长、演员、制作方、厂牌、系列、导演和分类。上游返回的媒体字段必须在服务端响应映射阶段剔除。

禁止向用户返回或主动生成：

- 视频文件、视频播放地址、预览流或封面媒体；
- 磁力链接、torrent、下载地址或网盘地址；
- 绕过来源站访问控制的链接或操作；
- 与查询无关的推荐、推广和外部群组邀请。

结果属于上游数据的文本索引，不表示产品拥有或分发原始媒体。详情页可展示上游记录的公开文本来源链接，但不承诺该链接可访问，也不包装成下载入口。

### 1.3 MVP 不解决的问题

不建设用户注册、会员、支付、广告、收藏、历史记录、订阅推送、排行榜、推荐、批量导出、群聊、Mini App、自建采集、跨来源去重、跨来源别名归一化、复杂全文检索或自动补全词库。

## 2. 用户、语言与产品决策

### 2.1 目标用户

目标用户是希望在 Telegram 中快速检索影片文本资料的个人用户。首版只支持私聊，不处理群聊中的公开查询，不要求用户拥有上游服务账户或填写自己的 API Key。

### 2.2 首版语言

首版支持中文和日文两种界面语言。

| 场景 | 规则 |
| --- | --- |
| 首次 `/start` | 根据 Telegram `language_code` 选择中文或日文；无法识别时默认中文 |
| 手动选择 | `/language` 或设置入口可切换中文/日本語 |
| 已保存语言 | 以后优先使用用户已选择的语言，不被单次消息语言覆盖 |
| 查询输入 | 影片编号、关键词和筛选值按用户原文提交；不自动翻译关键词 |
| 上游字段 | 原文标题和实体名称按上游返回展示；界面标签、错误提示和按钮翻译为当前语言 |
| 管理员状态 | 管理命令根据管理员当前语言返回；日志和内部错误使用英文标识 |

日文界面不能被当作中文界面的简单机器替换。按钮长度、日期格式、帮助内容和错误提示都需要分别定义并在验收时检查。

### 2.3 已确认的 MVP 决策

| 项目 | 决定 |
| --- | --- |
| 产品形态 | Telegram 原生 Bot |
| 入口 | 私聊，文本输入和内联按钮 |
| 数据来源 | 首版唯一接入 JavInfo；实际字段与能力以接入验证结果为准 |
| 数据策略 | 首版按需查询，不自建历史存量数据库 |
| 结果形式 | 文本列表、文本详情、内联翻页 |
| 默认每页 | 5 条 |
| 详情获取 | 查询结果先展示摘要，点击后按需获取详情 |
| 语言 | 中文、日文 |
| 失败策略 | 简单返回可理解的失败提示，用户主动重试 |
| 管理员 | 通过 Telegram 数字用户 ID 白名单识别 |
| 商业化 | MVP 不做支付、广告或额度售卖 |
| 成人确认 | 首次使用时确认已年满 18 岁；确认状态后续保留 |

## 3. 命令、菜单与权限

### 3.1 用户命令

| 命令 | 可用角色 | 行为 |
| --- | --- | --- |
| `/start` | 所有用户 | 创建或恢复用户资料，展示首页和语言选择状态 |
| `/help` | 所有用户 | 说明支持的输入、筛选、详情、返回和失败处理 |
| `/language` | 所有用户 | 选择中文或日本語 |
| `/cancel` | 所有用户 | 取消当前查询或筛选流程，返回首页 |
| `/privacy` | 所有用户 | 查看内容边界与数据说明，清除已保存的年龄确认状态 |
| `/status` | 管理员 | 查询上游账户余额、充值状态、限速和连通性 |

普通用户输入管理员命令时，只返回当前语言的“无权限”提示，不泄露命令存在的内部细节。普通用户的命令菜单不展示 `/status`；服务端仍必须对命令执行再次鉴权。

### 3.2 首页菜单

首页提供：开始查询、使用帮助、语言设置、隐私与内容说明、取消当前操作。首页不展示余额、计费、API Key、内部来源名称或运维状态。管理员可以在私聊中看到状态入口，但状态结果不出现在普通用户页面。

### 3.3 上游账户状态

`/status` 仅管理员可用，返回查询时间、账户接口是否连通、余额（如上游提供）、是否充值或可用状态、当前限速（如上游提供）。账户接口成功只代表账户接口可达，不代表每个数据源都正常。读取失败时返回“状态读取失败”，不能用旧缓存余额冒充实时值；充值流程不在 MVP 中实现。

## 4. 核心用户流程

### 4.1 首次进入

用户发送 `/start` 后，Bot 根据语言规则创建用户资料，展示当前语言、产品边界和“开始查询”入口。首次使用时必须先确认“我已年满 18 岁”，未确认前不能执行查询；取消或拒绝时只返回退出提示，不保存为已确认。确认只需完成一次，后续会话沿用状态，用户可以通过 `/privacy` 清除确认状态并重新确认。首页明确说明只返回文本元数据，不提供视频、下载或媒体链接。用户可以直接发送影片编号或关键词开始查询，也可以先打开帮助或语言设置。

### 4.2 查询

1. 用户发送非空文本。
2. Bot 立即发送或编辑为“正在查询…”的状态消息。
3. 服务端按当前语言和查询上下文调用上游搜索接口。
4. 成功后用一条结果消息展示摘要和内联按钮。
5. 用户点击条目进入详情，或点击筛选、翻页、重新查询。
6. 用户发送新的文本时创建新查询；旧请求迟到时不得覆盖新查询界面。

查询输入先去除首尾空白；空输入不调用上游，直接提示当前语言的输入示例。输入符合已定义影片编号格式时标记为编号查询，其他文本标记为关键词查询。当前适配器均通过搜索接口提交原文，打开详情时才按准确影片编号调用详情接口。首版不承诺纠正错别字、自动翻译、语义扩展或模糊匹配，是否支持模糊匹配取决于 JavInfo 接口能力并需在接入时明确。

### 4.3 结果列表

默认每页 5 条。每条显示序号、影片编号、文本标题、发行日期；制作方存在时追加展示。字段为空时整项省略，不显示 `null`、`undefined` 或空标签。

结果页包含条目详情、筛选、上一页/下一页、新查询、返回首页或取消。第一页不显示上一页。没有可靠总数时只显示“第 N 页”，不虚构总页数。下一页为空时保留当前页并提示已经没有更多结果，不把用户带到空白页面。

结果列表超过 Telegram 消息长度时缩短摘要，完整文本只在详情页展示。按钮文字按中文和日文分别控制长度，不能因日文标题过长导致布局超限。

### 4.4 文本详情

详情按当前语言的分组展示实际存在的字段：基本资料（影片编号、标题、发行日期、时长）、关联实体（演员、制作方、厂牌、系列、导演）、分类信息、来源信息。空分组不展示。上游专有的媒体字段、播放字段、下载字段和未验证字段不直接透传。详情提供“返回列表”，返回时恢复原查询条件、筛选条件和页码；不承诺恢复 Telegram 客户端的精确滚动位置。

编号和整理后的文本资料使用便于复制的普通文本格式；不承诺内联按钮可以直接写入用户剪贴板。

## 5. 查询与筛选

### 5.1 MVP 筛选字段

筛选区默认折叠，首版只提供以下常用字段：

| 字段 | 输入方式 | 规则 |
| --- | --- | --- |
| 演员 | 文本输入 | 按上游支持的匹配规则提交 |
| 制作方/厂牌 | 文本输入 | 上游支持时使用；不支持时明确提示 |
| 系列 | 文本输入 | 上游支持时使用 |
| 发行日期 | 起始日期、结束日期 | 使用明确日期格式，结束日期包含当天 |
| 时长 | 最短、最长分钟数 | 仅对有时长的记录生效 |
| 版本标记 | 暂不展示 | 尚无已核验的可靠映射，不属于当前可用筛选 |

首版不做多层筛选树、同一字段多选、任意条件表达式、演员排除、标签交集编辑或跨来源词汇自动归一化。输入值保留用户原文，不因为中日语言切换而翻译实体名称。

### 5.2 筛选交互

筛选页面展示当前已选条件摘要，提供“应用”“重置”“取消”。应用前不改变原结果页；应用成功后生成新查询并从第一页开始。重置清空筛选但保留原始关键词，取消返回之前结果页。

界面不承诺所有来源都支持每个字段。若某个字段无法传给上游，应在应用前提示该字段当前不可用，不静默伪装为已生效。排序首版只提供相关度和发行日期；默认排序按上游相关度或来源稳定顺序。

### 5.3 分页与结果一致性

分页使用上游支持的页码或游标。无法判断总数时不显示总页数。翻页按钮应携带短标识，完整查询条件保存在服务端短期状态中。

详情返回和分页按钮必须校验用户归属、查询状态版本和过期时间。数据源更新导致下一页结果变化属于可接受限制；历史页不要求持久化快照。

## 6. 数据来源与字段规则

### 6.1 上游能力边界

第三方 API 的鉴权、速率、计费、字段可空性、分页方式和错误码必须在接入前以实际文档和低额度调用验证。文档中未验证的能力不能写成产品承诺。

MVP 只依赖常规查询接口：关键词搜索、少量筛选、分页和单条详情。账户状态接口仅供管理员使用。若某能力需要商业合作、长期高额度或维护自建采集，不作为首版依赖。

### 6.2 字段映射

服务端建立供应商响应到产品字段的显式映射。每个字段记录来源字段、类型、可空性、中文/日文展示规则、是否允许列表展示、是否允许详情展示。

字段缺失时降级展示，不能使用猜测值补齐。日期保留来源语义；时长统一转换为分钟后展示；原始分类和制作方名称保留来源文本，不在 MVP 进行跨来源归一化。

响应映射阶段必须删除或拒绝以下字段：`sampleUrl`、`gallery*`、视频地址、`.m3u8`、磁力、torrent、下载链接及同类媒体访问字段。日志也不得记录这些字段的完整值。

### 6.3 来源链接

如 JavInfo 提供合法的公开记录链接，详情可提供“查看来源资料”按钮。该按钮只能打开文本记录来源，不添加重定向、下载代理、短链隐藏或媒体解析能力。来源链接失效时显示来源不可用，不改变其他文本字段；没有合适的公开文本链接时不显示该按钮。

## 7. 状态、错误与失败处理

| 状态 | 中文提示 | 日文提示 | 后续行为 |
| --- | --- | --- | --- |
| 加载中 | 正在查询… | 検索中… | 禁止同一操作重复提交 |
| 无结果 | 没有找到匹配记录，请修改关键词或筛选条件 | 条件に一致する情報が見つかりません。検索条件を変更してください | 保留输入，允许修改 |
| 下一页为空 | 已经没有更多结果了 | これ以上の結果はありません | 保留当前页 |
| 详情不存在 | 这条记录暂时无法查看 | この情報は現在表示できません | 返回列表 |
| 限速 | 请求较多，请稍后再试 | リクエストが多いため、しばらくしてから再試行してください | 用户稍后重试 |
| 余额不足 | 查询服务暂时不可用，请稍后再试 | 検索サービスを一時的に利用できません。後でもう一度お試しください | 普通用户不展示余额或充值信息 |
| 超时/未知异常 | 查询失败，请重试 | 検索に失敗しました。もう一度お試しください | 提供重试、返回列表 |
| 会话过期 | 此操作已过期，请重新发送关键词 | この操作は期限切れです。キーワードを再送信してください | 不执行旧按钮请求 |

应用等待上限暂定 20 秒，可配置。超时后结束加载并显示失败，不自动重复产生可能计费的上游请求。接口返回空数组按空结果处理；HTTP 200 不代表一定有记录。

MVP 不建设后台重试队列、自动切源、复杂熔断、故障修复流程或面向用户的服务状态页。失败只需要可理解地返回，并记录最低限度的内部错误类型。

## 8. 会话、隐私与数据留存

查询条件、当前页、结果标识和视图状态在服务端短期保存，以支持翻页、详情和返回；默认会话 TTL 为 30 分钟，过期后按会话失效处理。语言偏好和年龄确认随用户资料长期保存，不随查询会话过期。该状态不是历史资料库，不用于向用户提供历史查询。按钮不携带完整关键词、API Key 或敏感数据。

会话状态按用户和聊天隔离，按钮点击必须校验用户归属。会话保存在数据库中，单纯服务重启不会主动清除有效会话；状态过期、取消或版本不匹配后，旧按钮不执行未知查询。

首版不保存完整历史查询结果，不建立可供用户浏览的资料库。为快速确认 webhook 和去重，接收到的 Telegram 更新会暂存数据库收件箱；处理结束后清除消息正文，去重 ID 保留七天。未处理的 queued 更新可跨重启保留，需在隐私说明中说明该短暂存储。日志只记录请求耗时、上游状态码、内部错误类型、分页结果数量和匿名化的请求关联 ID，不记录 API Key、完整用户输入、完整来源响应或媒体地址。

用户可通过 `/cancel` 结束当前交互；MVP 不提供复杂的个人数据导出或删除后台，当前保留语言偏好、私聊标识和年龄确认时间；`/privacy` 可清除年龄确认及查询会话，不删除整个用户资料或语言偏好。完整用户资料删除能力尚未提供，后续需补齐清除方式。

## 9. 运行与管理要求

最低运行要求：应用可区分用户请求、上游失败和内部处理失败；每个请求有超时和基本限流，避免重复计费和 Telegram 回调堆积；上游 API Key 只存在服务端环境配置，不进入 Git、镜像日志、按钮参数或用户消息；只有管理员数字用户 ID 可以执行 `/status`；健康检查只说明 Bot 进程可用，不把它等同于上游数据源全部可用；记录最近一次上游调用成功/失败时间和错误类型，供管理员排查。

MVP 不要求建设公开 HTTP 管理后台、运营报表、复杂告警、自动扩容或多实例调度。

## 10. 验收标准

### 10.1 用户流程

1. 中文用户首次启动、完成年龄确认后，可完成查询、列表、详情、返回和新查询。
2. 日文用户首次启动、完成年龄确认后，可完成同一流程，按钮、提示和帮助内容均为日文。
3. 未完成年龄确认的用户不能执行查询；用户通过隐私入口清除确认状态后，下一次查询需要重新确认。
4. 用户可以切换语言，后续页面按新语言展示；正在进行的查询不会被语言切换错误覆盖。
5. 查询条件、筛选条件和页码在详情返回后保持一致。
6. 新查询或取消后的旧响应不会覆盖当前界面。

### 10.2 数据与安全边界

1. 列表和详情只出现允许的文本字段，不出现视频、预览流、磁力、torrent 或下载地址。
2. 缺失字段、长标题、特殊字符和中日文文本不会破坏 Telegram 消息格式。
3. 上游字段映射和不可用筛选有明确降级行为，不静默伪装成功。
4. API Key 不出现在消息、按钮参数和日志中。

### 10.3 失败与权限

1. 无结果、空下一页、详情缺失、限速、余额不足、超时和未知异常分别得到约定提示。
2. 失败不会让用户永久停留在加载状态，也不会因自动重试造成无界计费。
3. 普通用户不能读取余额、充值状态或限速；管理员命令服务端鉴权有效。
4. 旧按钮、过期会话和跨用户按钮点击不会执行查询。

## 11. 首版明确不包含

获客、广告、支付、会员、额度充值、订阅推送、收藏、历史、推荐、排行榜、群聊、Mini App、批量导出、自建历史数据库、自行爬取历史存量、跨来源合并、跨来源去重、别名归一化、自动翻译关键词、复杂搜索语法和媒体访问能力。
