# Telegram 内容频道矩阵 MVP PRD

版本：v0.1  
更新日期：2026-11-05

## 1. 产品目标

用少量、可复用的内容运营能力，启动多个中文垂直 Telegram 频道，验证不同内容方向能否持续提供读者价值。MVP 重点是尽快开始真实发布并收集可观察信号，不以自动化覆盖所有来源、建立统一品牌或证明收入为目标。

频道作为独立内容产品运营。每个频道有清楚的主题承诺和内容边界；底层尽量复用来源接入、内容处理、发布记录、邮件通知和效果观察能力，新增频道时主要补充频道配置和来源，而不是重做通用流程。

## 2. 当前决策

| 事项 | MVP 决策 |
|---|---|
| 试错方式 | 高试错、多品类；不同垂直频道分开运营 |
| 首批频道 | AI / 软件更新；PC 游戏优惠 |
| 语言 | 简体中文 |
| 读者范围 | 不锁定详细人口画像；每个频道保留可调整的读者假设 |
| 品牌 | 暂不要求统一品牌，不把矩阵品牌建设作为 MVP 目标 |
| 发布方式 | 满足校验规则后自动发布，不设置逐条人工确认 |
| 发布单元 | 每个频道每天一期「每日精选」，一期包含多条；不按候选逐条发帖 |
| 采集节奏 | 每日一次集中采集、筛选和组稿；Steam 入选商品发送前复查价格与有效期 |
| 单期数量 | 首版每期最多 5 条，不设凑数要求；不足 3 条也可成稿，无合格内容则不发空稿 |
| 通知 | 邮件报告发送结果和异常；不把邮件设置成发布审批 |
| 地区 | AI / 软件内容面向全球中文读者；游戏首版只保证 Steam 中国区价格，其他地区不承诺本地价格 |
| 淘汰规则 | PRD 保留独立板块，阈值后续根据观察数据讨论 |

## 3. 读者假设与 Prompt 的关系

读者范围目前不需要细分为年龄、职业等固定画像，但频道仍需要一个可操作的读者假设。读者假设不仅影响 Prompt，还影响来源选择、内容筛选、解释深度、地区标注、排除项和发布节奏。

MVP 使用轻量、可调整的假设：

- AI / 软件更新：面向希望用中文快速理解 AI 与软件产品重要变化的人；具体内容优先选择有明确影响、功能或使用场景的信息。
- PC 游戏优惠：面向关注 Steam 中国区 PC 游戏折扣、希望快速判断优惠是否值得点开的中文用户。

Prompt 是把频道的选品标准和表达风格转成文案的一个组件，不代替频道定位。每个频道独立维护可版本化的提示词和内容规则；共用的摘要字段、来源标注和安全约束尽量复用。

## 4. MVP 频道定义

### 4.1 AI / 软件更新

频道承诺：用简体中文筛选值得关注的 AI 与软件产品更新，并说明变化内容及其实际影响。

首版内容范围：

- 官方发布的模型、产品、功能和开发工具更新。
- 对目标读者有明确影响的重大版本或服务变化。
- 重要更新需说明“改了什么、谁会在意、读者可查看什么原始信息”。

暂不纳入：

- 泛 AI 行业新闻、观点评论和未经证实的传闻。
- 课程推广、纯营销稿、重复发布和只有标题变化的内容。
- 没有可靠原始出处或无法确认发布时间的消息。

首批主来源：

- OpenAI 官方 News RSS。
- Google AI 官方 Blog RSS。
- Hugging Face 官方 Blog RSS。

GitHub Changelog 可作为低优先级补充源，优先筛选与 AI、开发者工具直接相关的更新。Product Hunt、中文科技媒体及其他聚合源暂不自动接入；如果后续观察到主来源漏掉了有价值且稳定的内容，再评估其增量价值。

### 4.2 PC 游戏优惠

频道承诺：用简体中文筛选 Steam 中国区有代表性的 PC 游戏折扣，清楚标注价格地区和活动条件。

首版内容范围：

- Steam 中国区商店的游戏折扣。
- 优先收录折扣明显、游戏本身有可解释价值且活动仍有效的条目。
- 每条内容标注游戏名、折后价、折扣信息、适用商店地区、活动期限（来源提供时）和 Steam 商店链接。

暂不纳入：

- 其他商店的跨地区价格汇总。
- 无法确认地区、期限或领取条件的“免费领取”。
- DLC、道具、试玩、免费周末与永久免费游戏，除非后续为这些内容定义单独规则。

首批主来源：

- Steam 中国区商店折扣信息，使用商店页面链接作为读者核验入口。

GamerPower 可作为后续免费领取来源候选，但当前返回条目有大量缺失截止时间的记录，也存在已过期项目。本 MVP 不将其接入自动发布链路。Epic 免费游戏页本轮自动读取遇到访问限制，也不作为首发依赖。

## 5. 来源接入原则

来源接入按“主来源优先、边缘来源延后”执行。来源数量不是目标，新增来源必须能补足主来源没有覆盖的有效内容，且维护和使用条件可接受。

每个候选来源应记录：

- 来源名称、所有者、公开入口及获取方式。
- 语言、地区、更新时间和预期更新频率。
- 可获取字段、历史/当前覆盖情况及稳定性。
- 引用、署名、缓存、商业使用和再发布限制。
- 相对现有来源新增的合格内容量，而非接口返回总量。

优先链接回原始公告、发布页或商店页。来源可被读取不等于允许复制全文、图片或无限期保存。来源许可不明确、关键字段缺失或更新状态异常时，应跳过发布并发出邮件异常通知。

## 6. 内容发布要求

### 6.1 通用要求

- 发布语言为简体中文；专有名称保留原文并在需要时附简短解释。
- 每条内容包含标题、原创短摘要、原始来源链接和来源时间。
- 摘要只表达来源能支持的事实，不补写未经核实的推断。
- 同一事实或同一商品在多个来源出现时去重，优先保留权威、更新更及时的来源。
- 过期、重复、缺少来源、关键字段不完整或无法通过校验的候选不发布。
- 发布任务记录来源、生成时间、使用的频道规则/Prompt 版本、校验结果和 Telegram 消息标识，供回查和观察。

### 6.2 AI / 软件频道格式

整期标题为「AI产品雷达 · 每日精选」，注明运营日期和实际条目数。一期通过一条 Telegram 消息发出；每个条目编号，包含：

1. 简短更新标题。
2. 一至两句中文说明发生了什么，影响明确时一并说明；无法判断时不猜测。
3. 对应该条目的原始发布链接、来源和发布时间；不以一个通用链接代替全部来源。

### 6.3 游戏优惠频道格式

整期标题为「Steam折扣情报局 · 每日精选」，注明运营日期和实际条目数。每款游戏编号，包含：

1. 游戏名称及必要的平台/版本信息。
2. 突出中国区现价、划线原价及降价比例。
3. 一至两句简短游戏介绍。
4. 活动截止时间；来源没有提供或无法确认时，不制造截止时间，并按规则决定跳过或标注未知。
5. 对应该游戏的 Steam 商店链接；整期统一标注中国区 / CNY。

整期控制在 Telegram 单条消息长度内，超限时减少末尾低优先级条目，保留完整段落及来源，不默认拆成多条发布。候选、文案和校验记录仍逐条保留，发布与防重以「频道 + 运营日期 + 每日精选」为单元，并记录本期包含哪些候选。北京时间每天 09:00 在部署实例触发，采集、筛选和生成完成后发送；触发时间不是保证送达时刻。

## 7. 自动发布与异常处理

本阶段不设人工逐条确认。自动发布不是无条件发布：来源、时效、重复和必要字段校验均通过后才可发送；其他候选跳过并进入运行记录。

系统行为要求：

- 每日完成来源检查、候选整理、去重、中文摘要、规则校验和频道发布。
- 单一来源失败时继续处理其他可用主来源；记录失败，不将缺失来源伪装成“没有新内容”。
- 实例定时及 Codex 补跑共用每日发布记录；每频道每个北京时间自然日最多一期。Telegram 明确拒绝时可通过相同入口补跑；已发送或发送状态不明时禁止重发，不提供人工发送界面。删除 Telegram 消息也不解除当天发送限制。
- 避免因任务重跑而重复发布同一条内容。
- 对低置信度、来源冲突、过期状态不明或关键价格/资格字段不一致的内容采取跳过策略，并报告异常。

邮件通知至少说明：任务日期、各来源成功/失败、候选数、发布数、跳过数及原因、发送失败数、需要关注的异常。邮件用于运行可见性，不要求收件人批准后续发布。

## 8. 观察指标

MVP 先形成可用记录，不在开始前设淘汰阈值。初期筛选成本作为理解品类和来源的观察数据，不作为自动停更条件。

每条内容和每日运行尽量记录：

- 来源候选数、去重数、通过校验数、实际发布数及跳过原因。
- 来源可用性、过期/错误信息和纠错事件。
- 发布后可比时间点的 Telegram 浏览数；发布时刻和采样时刻同时保存。
- 每个来源带来的独有合格内容量。
- 人工检查或整理投入（如有），仅作为学习记录。
- 外链点击（若后续设置合规、可维护的追踪链接）；点击不能等同购买或游戏领取。

比较不同频道或内容类型时，按帖子年龄、语言、地区和内容类型分组。没有采集到的数据记为未知，不当作零。MVP 结果用于判断值得继续观察什么，不声称证明市场需求、增长或收入。

## 9. 扩展设计

新增频道应通过独立配置描述，不复制一套专属流水线。每个频道至少定义：

- 频道承诺和临时读者假设。
- 内容允许/排除范围及地区、语言规则。
- 主来源清单、来源优先级和回退策略。
- 内容字段、摘要格式、Prompt 版本和校验规则。
- 过期策略、去重规则和低置信度处理方式。
- 发布频率和该频道关注的效果指标。

共用能力按跨频道需求设计：来源登记与检查、标准化候选格式、去重、摘要生成、校验、发布防重、结果记录、邮件报告和观察数据采集。频道特有的来源字段或规则通过配置/适配层扩展，不为每个品类重写整套发布逻辑。

后续可评估但不纳入本次 MVP 的频道方向：垂直网络安全资讯、奖学金/竞赛/申请机会、职位精选、旅行优惠、书籍与文化发现、其他游戏商店和免费领取。进入候选不代表已决定上线；每个方向需先完成来源覆盖和使用条件评估。

## 10. 淘汰与加码规则（待讨论）

本板块保留，首版不设具体阈值。待积累足够的来源覆盖、内容发布、相近帖龄阅读和维护成本记录后，再讨论暂停、扩展或拆分频道的条件。不能仅凭订阅总数、单条爆款或单次来源故障淘汰一个品类。

## 11. 尚待后续讨论

- 每日一次采集及一期精选已确定；运行时区 Asia/Shanghai，每天 09:00 触发，处理完成后发送。
- 游戏折扣的最低折扣/价格筛选标准，以及“代表性游戏”的定义。
- AI / 软件更新的重要性分级标准。
- 邮件摘要的发送时间和异常分级。
- 点击追踪是否需要在 MVP 启用。
- 频道获客与推广方式；当前不假设新频道会自然增长。
- 服务器隔离、部署、API 接入和运行成本等技术方案。
- 淘汰与加码阈值。
