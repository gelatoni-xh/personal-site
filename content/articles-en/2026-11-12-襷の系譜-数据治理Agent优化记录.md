## 1. Whole-group lightweight judgment and bounded cross-check

**Problem/case:** simple organization variants do not fit safe general string replacements; person identity can reveal organization problems. “大東第1高校 / 大東大一高校” needs independent entity evidence. Seventeen uncertain identities among 44 rows do not mean seventeen conflicts or heavy calls.

**Change:** organization rules → one whole-group organization lightweight request → person rules → one whole-group person lightweight request → one cross-check → at most one organization adjudication and affected-person reassessment → bounded deeper research. The fixed DAG has no backward edge. Reject circular identity/organization evidence; do not add configurable sub-batches.

**Evidence/status:** implemented and deployed in [Agent PR #6](https://github.com/gelatoni-xh/tasuki-keifu-agent/pull/6), with regression coverage and stage metrics. The latest real attempt stopped before cross-check; complete live success is not established.

## 2. Protocol diagnostics and timeout propagation

**Problem/case:** a retry-limit message does not establish API unavailability. Unresolved responses included stray target IDs; provider diagnostics were insufficient; a configured 120000 ms timeout was not reliably propagated through the runner's 25000 ms default.

**Change:** ignore and warn on stray unresolved targets without authorizing a match. Keep structural and candidate checks. Persist safe call/stage/error-phase details, duration and provider/response IDs, status and output types when actually returned. Fix timeout propagation. Production explicitly selects `gpt-6.1-sol` through the pro route with 120000 ms. Never treat example settings as effective configuration or promise a provider ID when none was returned.

**Evidence/status:** deployed; configuration and propagation checked. The 25-second default was application-controlled, not an intrinsic model limit. See [PR #9](https://github.com/gelatoni-xh/tasuki-keifu-agent/pull/9) and the [timeout fix](https://github.com/gelatoni-xh/tasuki-keifu-agent/commit/0d86e25). Neither health checks nor diagnostics prove identity quality.

## 3. Human-readable failure reporting

**Problem:** failed emails looked almost empty; titles lacked event/group context; raw JSON obscured progress.

**Change:** batch alert titles identify event and group; event summaries name the event. Recover completed work and actual calls from durable journals without double-counting saved executions. Show readable states, funnels, calls and issues first, with raw metrics expandable. Unknown values stay unknown; dry-run writes remain zero.

**Evidence/status:** deployed in [Agent PR #13](https://github.com/gelatoni-xh/tasuki-keifu-agent/pull/13), [site PR #16](https://github.com/gelatoni-xh/personal-site/pull/16), and the title changes in Agent PR #6. Complete independent attempt-level navigation and all pricing coverage remain follow-up work. The next real run must establish practical reporting quality.

**Evidence/status:** deployed in [Agent PR #15](https://github.com/gelatoni-xh/tasuki-keifu-agent/pull/15). On the same saved context, offline serialization changed:

## 6. Historical-entry rules and per-item downgrade: this fix

**Problem:** absent Membership caused unnecessary uncertainty despite strong historical evidence; one poorly cited lightweight verdict blocked its valid peers.

**Cases:** 羽生祥成 and others had exact kanji/kana and same-canonical-organization history without Membership. 村中悠隼 had historical DNS registration, useful for identity but not participation. 伊藤亘輝 / 伊藤光輝 and 吉田大雅 / 吉田大河 exposed weak homophones. 杉野主宙, 竹原勇生 and 澤田聡太 still require independently resolved organization variants/IDs. 飯田翔真's prior 法政大学第二 affiliation differs from 小田原 NR; any remaining question concerns identity/affiliation evidence, not DNS itself.

**Change:** `exact_name_kana_historical_organization` requires a unique exact kanji/kana candidate, a sourced entry from another race no later than this race, identical existing canonical organization IDs, no contradictory cohort and no competing Membership-based candidate. DNS can support identity without creating a start, grade or Membership. Preserve weak candidates for cross-check.

A person lightweight match lacking target-owned independent evidence, unless an explicit birth date matches, becomes per-item unresolved with original target, reason and citations retained. Preserve valid peers and pass both domains' decisions, rule traces, candidates and warnings to cross-check. Unknown citations, foreign targets, malformed structure and explicit birth-date contradictions remain blocking. No tools or weaker identity safeguards were added.

**Evidence/status:** deployed via [Agent PR #17](https://github.com/gelatoni-xh/tasuki-keifu-agent/pull/17). Rule `2026-11-13.1`; policy `whole-group-cross-check/4`. All 36 unit and 15 disposable PostgreSQL integration tests passed, covering DNS and weak-homophone positives and negatives for missing kana, different organizations, future/current-race history, missing sources, duplicate exact candidates, cohort contradictions, invalid per-item citations and cross-check rejection. CI found three optional-field assertion typing issues; these were fixed and checks passed before merge.

**Unmeasured:** no rerun means no measured reductions in lightweight/heavy items, cost or total time, and no verified final success rate or new business facts. Tests and candidate estimates must not be reported as production gains.
