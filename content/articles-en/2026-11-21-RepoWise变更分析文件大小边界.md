## Two coverage ranges for the same change

[RepoWise](https://github.com/repowise-dev/repowise) provides repository analysis and documentation generation. Its change-health analyzer examines the health of changes, while diff risk checks changes for risk signals. [Issue #5780](https://github.com/repowise-dev/repowise/issues/5780) identified different input limits: change health accepted up to 1,500,000 bytes, but diff risk accepted only 1,000,000.

A text source file of roughly 1.2 MB could therefore enter health analysis while being skipped by diff risk. The two analyzers had a subtle coverage gap when examining the same change.

## Share the size policy and preserve separate responsibilities

The fix defines `MAX_CHANGE_ANALYSIS_FILE_BYTES = 1_500_000` in the shared analysis package and has both analyzers reference it. Choosing the higher existing limit preserves change health's coverage. Lowering both limits to 1,000,000 bytes would instead exclude files that change health already accepted.

Diff risk can consequently read up to 500,000 additional bytes per revision side, without increasing change health's existing parsing limit. The traverser's 8 MiB indexing ceiling serves a different workload and is not used as the shared change-analysis limit.

A shared size policy does not require identical input filtering. Each module retains its existing binary checks, including differences in how much input is inspected for NUL bytes. The change addresses the size boundary without also changing those filtering semantics.

## Constrain coverage with boundary tests

New tests cover inputs of 1,000,000, 1,200,000, and 1,500,000 bytes, plus one byte beyond the shared limit. They verify that both analyzers agree on the size boundary and that diff risk skips a change when either its base or head exceeds the limit. Additional coverage protects each module's existing binary behavior.

The focused local tests passed all 170 cases, and `ruff check .` passed. An expanded comparison run passed 227 tests and failed two Go cases because the reused environment lacked `tree_sitter_go`; neither failure exercised the changed size boundary. The full provider and unit suites were not run locally. Upstream Python 3.12 tests passed across three shards. At the merge-status check, the PR had 17 successful checks and three skipped checks, with Integration tests successful.

Maintainer `RaghavChamadiya` approved and merged [PR #5863](https://github.com/repowise-dev/repowise/pull/5863) on November 21, 2026, closing the linked issue. AI assisted with this contribution. The central decision was which modules share a resource policy: close the coverage gap while keeping indexing, parsing, and text-checking budgets distinct.
