## A getter that could change scanning behavior

Apache OpenNLP's `DefaultEndOfSentenceScanner` uses a set of characters to find sentence boundaries. [Issue #1581](https://github.com/apache/opennlp/issues/1581) reported that `getEOSCharacters()` returned its internal `Set<Character>` directly. A caller could add or remove characters from that set and change later scanning results.

A maintainer asked for an unmodifiable return value. The boundary matters because callers should be able to inspect the configured characters without changing scanner behavior through a getter.

## Document the contract and test it

The fix returns `Collections.unmodifiableSet(eosCharacters)` from `DefaultEndOfSentenceScanner.getEOSCharacters()` and documents the unmodifiable result in the `EndOfSentenceScanner` interface Javadoc. A regression test calls the method through the interface, attempts to add a character, and expects `UnsupportedOperationException`.

An unmodifiable view preserves read access without copying the set on every call. It is not an independent snapshot; the change prevents callers from mutating the internal set through this return value. Before submitting, we checked upstream usages: production code uses sentence scanners through `getPositions(...)`, and we found no caller modifying this returned set. A similarly named method on `SentenceDetectorFactory` returns `char[]` and is unrelated to this API.

## Verification and merge

With JDK 21, the local `./mvnw -pl opennlp-core/opennlp-runtime -am verify` run passed 1,310 API tests with one skipped, 4,489 Runtime unit tests, and 19 Runtime integration tests. Checkstyle, RAT, and forbiddenapis also passed. These results cover the selected Maven reactor, not every module in the repository.

Upstream CI passed the ASF Allowlist check, Java 21 and 25 builds on Ubuntu, macOS, and Windows, and Shell Tests on all three platforms. Both `rzo1` and `mawiesne` approved the change. [PR #1584](https://github.com/apache/opennlp/pull/1584) merged on November 18, 2026, closing the issue.

The patch was small, but the mutability of an API return value affected object behavior. We translated the maintainer's request into an interface contract and an executable regression test, and described the scope of AI assistance and human review when submitting the contribution.
